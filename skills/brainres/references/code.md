# Code and debugging answers

1. **Explanation next to the code it explains:** a comment on the line, or one sentence right after the block. No "see above". (#6)
2. **One complete worked example with the user's real names, paths and values**, not `foo`/`bar`. (#10, #49)
3. **Start with the first action**, and add recovery: "If you see `EADDRINUSE`, run `lsof -i :3000`." (#11)
4. **Copyable things go in code blocks.** Prose stays outside. (#50)
5. **Give a way to verify**: a command, a test, or the expected output. Explanations raise acceptance even when wrong, so let the user check. (#85)
6. **Keep code, errors, paths and flags verbatim.** Never paraphrase an error message.
