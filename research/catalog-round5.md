# Catalog round 5: how people use LLM coding help (2022–2024)

Compiled 2026-11-12 in a research round (the backlog was empty). Prefix `DV-`. Classic program-comprehension research (beacons, plans, chunking, identifiers) is already in [catalog HC §K](catalog-hci-infodesign.md). This round adds empirical studies of people reading and using **LLM-generated** code help. Sources were checked against arXiv abstracts and full text where marked. Most studies are small or single-course, so grades are M or W.

| ID | Concept | Mechanism | Source | Ev | Applies | Rule | Situation |
|---|---|---|---|---|---|---|---|
| DV-01 | Summary beats line-by-line for code explanations | In an e-book with LLM explanations, students "seemed to prefer the summary explanations most". Line-by-line was viewed most (58.5%, leftmost button) but rated least useful for learning (Kruskal-Wallis n.s.). Viewing time tracked snippet length (r = .92) | MacNeil et al. 2023, SIGCSE (full text checked) | W | Yes | Explaining code: a 1-sentence summary of what it does comes first; line notes only for the 1–3 non-obvious lines | code |
| DV-02 | LLM explanations rated clearer than students' | Students rated LLM code explanations significantly easier to understand and more accurate than peer-written ones (large course) | Leinonen et al. 2023, ITiCSE (abstract checked) | M | No | Validates using LLM explanations at all; implies no formatting rule | n/a |
| DV-03 | Scaffolded help without full solutions | About 700 students made 8,000 uses over 12 weeks, mostly for concepts and debugging. Design principles: avoid direct answers while encouraging learning, and keep students in control. The tool annotates the student's own incorrect code with fixes | Kazemitabaar et al. 2024, CHI (abstract + blog checked) | M | Yes | For learners, mark the fix on *their* code (which line, why) rather than replacing it with a fresh solution; the full solution stays available on request | learn |
| DV-04 | GenAI widens the gap for struggling novices | Known metacognitive difficulties persisted and some were compounded. Three new ones appeared: Progression, Interruption, Mislead. Struggling students believed they understood more than they did (n = 21 with AI) | Prather et al. 2024, ICER (abstract checked) | W | Partial | After giving a learner working code, add one self-test ("what does this print if the list is empty?"), never "makes sense?" | learn |
| DV-05 | Context-grounded explanations aid task completion | An in-IDE LLM that explains the user's highlighted code, with the program as context, raised task completion over web search (n = 32). Students and professionals used it differently | Nam et al. 2024, ICSE (abstract checked) | M | Partial | Explain the API call *in their code* (their arguments, their data), not the API in general | code |
| DV-06 | Generated code is hard to verify | 19 of 24 preferred Copilot, but it did not reliably speed tasks up. Participants struggled to understand, edit and debug its output | Vaithilingam et al. 2022, CHI EA (abstract; difficulty finding via secondary source) | W | Partial | After non-trivial generated code, name the 1–2 lines most likely to need changing for their case | code |
| DV-07 | Unmet requirements drive non-use | In a survey of 410 developers, the top reason for not using AI assistants was output that misses functional or non-functional requirements | Liang, Yang & Myers 2024, ICSE (secondary summaries; full text not checked) | W | Partial | When requirements are unstated, put the assumptions in one line above the code (version, dependencies, input shape) | code |
