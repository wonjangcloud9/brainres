<!-- Q: OAuth랑 JWT 차이가 뭐예요? -->

OAuth는 "누가 누구에게 어떤 권한을 위임할지 정하는 절차(프로토콜)"이고, JWT는 "정보를 담아 서명한 토큰의 형식"이라서 서로 비교 대상이 아니라 다른 층위의 개념이에요.

**OAuth 2.0**
- 목적: 앱이 사용자 비밀번호 없이 다른 서비스의 자원에 접근하도록 허용(위임)하는 것.
- 예: "구글로 로그인"할 때, 앱이 구글 계정 비밀번호를 받지 않고 접근 권한만 받아요.
- 토큰이 무엇인지는 정하지 않아요. 불투명한 랜덤 문자열이어도 되고 JWT여도 돼요.

**JWT (JSON Web Token)**
- 목적: 클레임(사용자 ID, 만료 시간 등)을 JSON으로 담고 서명한 토큰 형식.
- 구조: `헤더.페이로드.서명` 세 부분을 Base64URL로 인코딩해 이어 붙여요.
- 서버가 DB 조회 없이 서명만 검증해 토큰을 믿을 수 있어요.

| 구분 | OAuth 2.0 | JWT |
|---|---|---|
| 종류 | 인가 프로토콜 | 토큰 형식 |
| 답하는 질문 | "이 앱에 무엇을 허용할까?" | "이 토큰에 어떤 정보가 있고 진짜인가?" |
| 단독 사용 | 토큰 형식이 필요함 | 프로토콜 없이도 쓰임 (자체 로그인 세션 등) |

**함께 쓰는 방식:** OAuth의 액세스 토큰을 JWT로 발급하는 경우가 흔해요. OpenID Connect의 ID 토큰은 반드시 JWT예요.

**주의:** JWT 페이로드는 암호화가 아니라 인코딩이라 누구나 읽을 수 있어요. 비밀번호 같은 민감 정보는 넣으면 안 돼요. 또 서명 방식으로 발급된 JWT는 만료 전에 폐기하기 어려워서, 수명을 짧게 두는 편이 안전해요.

어떤 상황(소셜 로그인, 자체 API 인증 등)에 쓰실지 알려주시면 그에 맞는 구성을 골라 드릴게요.
