도커(Docker)와 가상머신(VM)은 둘 다 "격리된 환경"을 만든다는 점에서 비슷하지만, 격리하는 방식이 다릅니다.

## 핵심 차이: 무엇을 격리하느냐

- **가상머신(VM)**: 하이퍼바이저(VirtualBox, VMware, Hyper-V 등) 위에 **완전한 게스트 OS**를 통째로 띄웁니다. 각 VM은 자기만의 커널을 가집니다.
- **도커(컨테이너)**: 호스트 OS의 **커널을 공유**하고, 프로세스·파일시스템·네트워크만 분리합니다. 게스트 OS가 없습니다.

```
[VM]                          [Docker]
앱A   앱B                      앱A    앱B
Bins  Bins                     Bins   Bins
게스트OS  게스트OS              ─────────────
하이퍼바이저                    도커 엔진
호스트 OS                       호스트 OS
하드웨어                        하드웨어
```

## 주요 차이점

| 구분 | 가상머신 | 도커 |
|---|---|---|
| 격리 수준 | 높음 (커널부터 분리) | 상대적으로 낮음 (커널 공유) |
| 크기 | 수 GB (OS 포함) | 수 MB~수백 MB |
| 시작 시간 | 분 단위 | 초 단위 이하 |
| 성능 오버헤드 | 상대적으로 큼 | 거의 없음 |
| 다른 OS 실행 | 가능 (Windows 위에 Linux 등) | 제한적 (Linux 커널 기반) |
| 보안 | 커널 취약점 영향이 적음 | 커널 취약점이 전체 컨테이너에 영향 가능 |

## 실무에서 어떻게 쓰나

- **VM**: 서로 다른 OS가 필요하거나, 보안 격리가 중요하거나, 서버 자원을 통째로 나눠야 할 때 적합합니다.
- **도커**: 애플리케이션을 빠르게 배포·확장하거나, 개발/운영 환경을 동일하게 맞추거나, 마이크로서비스를 구성할 때 적합합니다.

참고로 macOS에서는 도커도 내부적으로 경량 Linux VM 위에서 컨테이너가 돌아갑니다. 그래서 Mac에서 도커를 쓰면 실제로는 VM과 컨테이너가 함께 동작하는 구조입니다.
