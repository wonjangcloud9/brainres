<!-- Q: OAuth랑 JWT 차이가 뭐예요? -->

OAuth는 권한을 위임하는 절차(프로토콜)이고, JWT는 정보를 담는 토큰의 형식이에요. 그래서 둘은 대체 관계가 아니라 함께 쓰는 경우가 많아요.

| | OAuth 2.0 | JWT |
|---|---|---|
| 정체 | 인가 프레임워크 (절차) | 토큰 포맷 (데이터 구조) |
| 답하는 질문 | "이 앱에 내 데이터 접근을 허락할까?" | "이 토큰에 어떤 정보가 담겼고 위조되지 않았나?" |
| 구성 | 역할(사용자, 클라이언트, 인가 서버, 리소스 서버)과 흐름 | `헤더.페이로드.서명` 세 부분 |
| 주 사용처 | "구글로 로그인", 외부 API 접근 허용 | 로그인 세션, API 인증, 서버 간 전달 |

**OAuth**는 사용자가 비밀번호를 넘기지 않고 제3의 앱에 제한된 권한을 주는 방법이에요. 예를 들어 어떤 사진 앱이 내 구글 드라이브를 읽으려 해요. 구글 로그인 화면에서 "허용"을 누르면, 앱은 비밀번호 대신 액세스 토큰을 받아요.

**JWT**는 그 토큰이 가질 수 있는 모양 중 하나예요. 예를 들어 `{"sub":"user123","exp":1767225600}`를 서버 비밀키로 서명해요. 서버는 DB 조회 없이 서명만 검증해도 사용자를 알 수 있어요.

**연결점**: OAuth의 액세스 토큰은 형식이 정해져 있지 않아요. 그래서 JWT를 쓰기도 하고, 의미 없는 랜덤 문자열(opaque token)을 쓰기도 해요.

**주의**: JWT는 발급 후 서버가 즉시 무효화하기 어려워요. 그래서 만료 시간을 짧게 잡고 리프레시 토큰을 따로 두는 편이 안전해요.

만드는 서비스가 "외부 앱에 권한을 줄 일"인지, "자체 로그인만 필요한 일"인지 알려 주시면 어느 쪽이 맞는지 구체적으로 짚어 드릴게요.
