<!-- Q: OAuth랑 JWT 차이가 뭐예요? -->

OAuth는 "권한을 위임하는 절차"이고, JWT는 "정보를 담은 토큰의 형식"이에요. 둘은 같은 층위가 아니라서 비교 대상이라기보다 함께 쓰는 경우가 많아요.

| | OAuth 2.0 | JWT |
|---|---|---|
| 정체 | 인가(authorization) 프로토콜 | 토큰 포맷 (RFC 7519) |
| 답하는 질문 | "이 앱이 내 데이터에 접근해도 되나?" | "이 토큰에 무슨 정보가 들었고, 위조되지 않았나?" |
| 구성 | 역할(사용자, 클라이언트, 인가 서버, 리소스 서버)과 흐름(grant) | `헤더.페이로드.서명` 세 부분을 Base64URL로 인코딩 |

**OAuth**는 비밀번호를 넘기지 않고 제3자 앱에 제한된 권한을 주는 방법이에요. "구글로 로그인"이나 "깃허브 연동"에서 써요. 예를 들어 노션이 내 구글 캘린더를 읽으려 할 때, 구글 로그인 화면에서 "캘린더 읽기"만 승인하면 노션은 비밀번호 없이 액세스 토큰만 받아요.

**JWT**는 서버가 서명해서 발급하는, 스스로 내용을 설명하는 토큰이에요. 서버가 세션 저장소를 조회하지 않고도 검증할 수 있어서 API 인증에 많이 써요. 예를 들어 `{"sub":"user42","exp":1790000000}`을 서명해 보내면, 서버는 서명만 확인하고 user42로 인식해요.

**함께 쓰는 방식:** OAuth 흐름에서 발급되는 액세스 토큰의 형태를 JWT로 정할 수 있어요. 하지만 OAuth 토큰이 꼭 JWT인 것은 아니에요. 불투명한 랜덤 문자열일 수도 있어요. 반대로 JWT를 OAuth 없이 자체 로그인에만 써도 돼요.

**주의할 점:** JWT 페이로드는 암호화가 아니라 인코딩이라 누구나 읽을 수 있어요. 비밀번호 같은 민감 정보를 넣으면 안 돼요. 또 발급 후 만료 전에는 폐기하기 어려워서, 만료 시간을 짧게 잡고 리프레시 토큰을 함께 쓰는 게 일반적이에요.
