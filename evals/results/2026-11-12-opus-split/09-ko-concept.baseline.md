# 도커 vs 가상머신

가장 큰 차이는 **무엇을 가상화하느냐**입니다.

- **가상머신(VM)**은 **하드웨어**를 가상화합니다. 각 VM이 자기만의 OS(커널 포함)를 통째로 가집니다.
- **도커(컨테이너)**는 **OS 수준**에서 격리합니다. 호스트의 커널을 공유하고, 프로세스만 분리된 공간에서 실행합니다.

## 구조 비교

```
      가상머신                        도커
┌──────┐ ┌──────┐            ┌──────┐ ┌──────┐
│ App  │ │ App  │            │ App  │ │ App  │
│ Libs │ │ Libs │            │ Libs │ │ Libs │
│GuestOS│ │GuestOS│           └──────┘ └──────┘
└──────┘ └──────┘            ┌────────────────┐
┌────────────────┐           │ Docker Engine  │
│   Hypervisor   │           ├────────────────┤
├────────────────┤           │ Host OS (커널)  │
│    Host OS     │           ├────────────────┤
├────────────────┤           │    Hardware    │
│    Hardware    │           └────────────────┘
└────────────────┘
```

## 주요 차이점

| 항목 | 가상머신 | 도커 |
|---|---|---|
| 격리 단위 | OS 전체 | 프로세스 |
| 커널 | VM마다 별도 | 호스트와 공유 |
| 크기 | 수 GB | 수십~수백 MB |
| 시작 시간 | 수십 초~분 | 1초 내외 |
| 리소스 오버헤드 | 큼 | 작음 |
| 격리 수준(보안) | 강함 | 상대적으로 약함 |
| 다른 OS 실행 | 가능 (Linux에서 Windows 등) | 호스트 커널과 같은 계열만 가능 |

## 언제 무엇을 쓰나

**도커가 적합한 경우**
- 개발/배포 환경 통일 ("내 컴퓨터에선 되는데..." 문제 해결)
- 마이크로서비스, CI/CD
- 빠르게 띄우고 지우는 작업

**가상머신이 적합한 경우**
- 완전히 다른 OS가 필요할 때
- 강한 보안 격리가 필요할 때 (멀티테넌트, 악성코드 분석 등)
- 커널 수준 설정이나 드라이버를 다뤄야 할 때

## 참고: macOS의 경우

macOS 커널은 Linux가 아니기 때문에, Mac에서 Docker Desktop을 쓰면 **내부적으로 경량 Linux VM을 하나 띄우고** 그 안에서 컨테이너를 실행합니다. 그래서 Mac에서는 Linux보다 파일 I/O 같은 부분이 조금 느릴 수 있습니다.

**한 줄 요약:** VM은 "컴퓨터를 통째로 하나 더 만드는 것"이고, 도커는 "같은 컴퓨터 안에 격리된 방을 만드는 것"입니다.
