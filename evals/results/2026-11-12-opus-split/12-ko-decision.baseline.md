핵심 기준은 **데이터가 바뀌어야 하느냐**입니다.

## 리스트 (`list`)를 쓸 때
- 요소를 **추가·삭제·수정**해야 할 때
- 같은 종류의 데이터가 **개수가 정해지지 않은 채** 모일 때

```python
scores = [90, 85, 77]
scores.append(100)      # 계속 늘어나는 데이터
```

## 튜플 (`tuple`)을 쓸 때
- 값이 **고정**되어 바뀌면 안 될 때
- 위치마다 **의미가 다른** 데이터를 묶을 때 (일종의 "레코드")
- **딕셔너리 키**나 **set 원소**로 써야 할 때 (튜플은 해시 가능, 리스트는 불가)
- 함수에서 **여러 값을 반환**할 때

```python
point = (3, 4)                  # x, y 좌표
location = {(37.5, 127.0): "서울"}  # 딕셔너리 키로 사용

def min_max(nums):
    return min(nums), max(nums)  # 튜플로 반환
```

## 기타 차이
| | 리스트 | 튜플 |
|---|---|---|
| 변경 가능 | O | X |
| 해시 가능 (dict 키) | X | O (내부 요소도 불변이면) |
| 메모리·생성 속도 | 약간 큼 | 약간 작고 빠름 |
| 메서드 | 많음 (`append`, `sort` 등) | `count`, `index`만 |

성능 차이는 대부분 체감하기 어려울 정도라서 선택 기준으로 삼을 필요는 거의 없습니다.

## 추천
- **기본은 리스트**를 쓰세요.
- **"이 값은 바뀌면 안 된다"** 또는 **"이건 하나의 묶음이다"**라는 의도를 드러내고 싶을 때 튜플을 쓰세요.
- 튜플 요소가 많아져서 `p[0]`, `p[1]`의 의미가 헷갈린다면 `namedtuple`이나 `dataclass`를 고려하세요.

```python
from typing import NamedTuple

class Point(NamedTuple):
    x: float
    y: float

p = Point(3, 4)
print(p.x)  # 인덱스 대신 이름으로 접근
```
