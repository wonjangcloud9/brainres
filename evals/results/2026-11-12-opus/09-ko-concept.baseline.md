# 도커(컨테이너) vs 가상머신(VM)

가장 큰 차이는 **무엇을 가상화하느냐**입니다.

- **가상머신**: **하드웨어**를 가상화합니다. 각 VM이 자기만의 OS(커널 포함)를 통째로 가집니다.
- **도커**: **OS(프로세스 환경)**를 격리합니다. 호스트의 커널을 공유하고, 앱과 라이브러리만 따로 묶습니다.

## 구조 비교

```
   가상머신                          도커 컨테이너
┌──────┬──────┬──────┐         ┌──────┬──────┬──────┐
│ App A│ App B│ App C│         │ App A│ App B│ App C│
│ Libs │ Libs │ Libs │         │ Libs │ Libs │ Libs │
│Guest │Guest │Guest │         ├──────┴──────┴──────┤
│  OS  │  OS  │  OS  │         │   Docker Engine    │
├──────┴──────┴──────┤         ├────────────────────┤
│     Hypervisor     │         │   Host OS (커널)    │
├────────────────────┤         ├────────────────────┤
│  Host OS / 하드웨어  │         │      하드웨어        │
└────────────────────┘         └────────────────────┘
```

## 주요 차이점

| 항목 | 가상머신 | 도커 |
|---|---|---|
| 격리 단위 | OS 전체 | 프로세스 |
| 커널 | VM마다 별도 | 호스트와 공유 |
| 크기 | 수 GB | 수 MB ~ 수백 MB |
| 시작 속도 | 수십 초 ~ 분 | 보통 1초 내외 |
| 자원 사용 | 무거움 (OS마다 메모리 점유) | 가벼움 |
| 격리/보안 수준 | 강함 (커널이 분리됨) | 상대적으로 약함 (커널 공유) |
| 다른 OS 실행 | 가능 (리눅스 위에 윈도우 등) | 기본적으로 호스트 커널과 같은 계열만 |
| 대표 도구 | VMware, VirtualBox, Hyper-V, KVM, UTM | Docker, Podman |

## 언제 뭘 쓰나

**도커가 적합한 경우**
- 앱 배포, 개발 환경 통일 ("내 컴퓨터에선 되는데?" 문제 해결)
- 마이크로서비스, CI/CD 파이프라인
- 같은 서버에 서비스를 많이, 빠르게 띄워야 할 때

**VM이 적합한 경우**
- 완전히 다른 OS가 필요할 때 (예: 맥에서 윈도우 실행)
- 강한 보안 격리가 필요할 때 (멀티테넌트, 악성코드 분석 등)
- 커널 수정이나 커널 수준 테스트가 필요할 때

## 참고: 맥에서 도커를 쓰면?

도커 컨테이너는 **리눅스 커널** 기능(namespaces, cgroups)에 의존합니다. macOS에는 리눅스 커널이 없기 때문에, Docker Desktop은 내부적으로 **경량 리눅스 VM을 하나 띄우고** 그 안에서 컨테이너를 실행합니다. 그래서 맥에서는 사실상 두 기술을 함께 쓰는 셈입니다.

한 줄 요약: **VM은 "컴퓨터를 통째로 하나 더" 만드는 것이고, 도커는 "앱이 쓸 격리된 방"만 만드는 것**입니다.
