<!-- Q: 도커랑 가상머신 차이가 뭐야? -->

도커는 호스트 OS의 커널을 공유하는 프로세스 단위 격리이고, 가상머신은 하드웨어까지 가상화해서 OS를 통째로 따로 돌리는 방식이에요.

| | 도커 (컨테이너) | 가상머신 |
|---|---|---|
| 격리 단위 | 프로세스 (커널 공유) | 전체 OS (커널 별도) |
| 시작 시간 | 보통 1초 안팎 | 보통 수십 초~분 |
| 크기 | 수십~수백 MB | 수 GB |
| 성능 오버헤드 | 거의 없음 | 하이퍼바이저 때문에 있음 |
| 격리 강도 | 상대적으로 약함 | 강함 |
| 다른 OS 실행 | 불가 (같은 커널만) | 가능 |

**커널 공유 여부**가 핵심 차이예요. VM은 하이퍼바이저 위에 게스트 OS를 올려서 각자 커널을 가져요. 그래서 무겁지만 서로 완전히 분리돼요. 컨테이너는 리눅스의 namespace와 cgroup으로 프로세스를 가둘 뿐이라 가볍고 빨라요. 대신 커널 취약점이 생기면 호스트까지 영향을 받을 수 있어요.

맥에서 도커를 쓰는 경우는 하나 더 알아야 해요. 도커 컨테이너는 리눅스 커널이 필요해서, Docker Desktop이 내부에 작은 리눅스 VM을 띄우고 그 안에서 컨테이너를 돌려요. 지금 쓰시는 darwin 환경이라면 도커 안에도 VM이 하나 있는 셈이에요.

고르는 기준은 간단해요. 같은 리눅스 기반 앱을 빠르게 배포하고 복제하려면 도커, 다른 OS가 필요하거나 강한 격리가 필요하면 VM이 맞아요.
