## 프로세스 vs 스레드

**프로세스**는 실행 중인 프로그램의 단위로, OS가 독립된 메모리 공간(코드, 데이터, 힙, 스택)과 자원(파일 디스크립터 등)을 할당해 줍니다. **스레드**는 프로세스 안에서 실행되는 흐름의 단위로, 같은 프로세스의 스레드끼리 대부분의 자원을 공유합니다.

### 핵심 차이

| 구분 | 프로세스 | 스레드 |
|---|---|---|
| 메모리 | 독립된 주소 공간 | 코드·데이터·힙 공유, **스택·레지스터만 개별** |
| 생성/전환 비용 | 큼 (컨텍스트 스위칭 무거움) | 작음 |
| 통신 | IPC 필요 (파이프, 소켓, 공유 메모리 등) | 공유 메모리로 직접 통신 |
| 안정성 | 하나가 죽어도 다른 프로세스는 영향 적음 | 하나가 크래시하면 프로세스 전체가 죽을 수 있음 |
| 동기화 문제 | 상대적으로 적음 | 레이스 컨디션, 데드락 → 락/뮤텍스 필요 |

### 직관적인 비유
- 프로세스 = 각자 독립된 **가게** (자기 주방, 재료, 장부를 따로 가짐)
- 스레드 = 한 가게 안의 **직원들** (주방과 재료는 공유하되, 각자 자기 작업을 수행)

### 언제 무엇을 쓰나
- **프로세스**: 격리가 중요할 때 (브라우저의 탭별 프로세스, 보안 경계, 장애 격리)
- **스레드**: 데이터를 자주 공유하고 가볍게 동시 작업해야 할 때 (웹 서버의 요청 처리, UI와 백그라운드 작업 분리)

### 참고
- Python은 GIL 때문에 CPU 바운드 작업에서 스레드로 병렬성을 얻기 어려워, 이때는 `multiprocessing`을 쓰는 경우가 많습니다. (최근 버전의 free-threaded 빌드는 예외)
- 스레드도 OS 입장에서는 스케줄링 단위이고, 프로세스는 자원 할당의 단위라고 구분하기도 합니다.

더 깊이 궁금한 부분(컨텍스트 스위칭, 동기화, 코루틴과의 차이 등)이 있으면 말씀해 주세요.
