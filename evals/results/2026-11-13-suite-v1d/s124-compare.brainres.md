<!-- Q: SQL이랑 NoSQL 차이 정리해줘. -->

SQL은 정해진 표 구조에 관계를 맺어 저장하고, NoSQL은 구조를 느슨하게 두고 확장과 유연성을 우선해요.

| 항목 | SQL (MySQL, PostgreSQL) | NoSQL (MongoDB, Redis 등) |
|---|---|---|
| 데이터 모델 | 행과 열이 있는 표, 표끼리 JOIN | 문서, 키-값, 컬럼, 그래프 |
| 스키마 | 미리 정의해야 하고 변경 비용이 큼 | 유연해서 필드를 자유롭게 추가 |
| 확장 | 주로 서버 성능을 올리는 수직 확장 | 서버를 늘리는 수평 확장에 유리 |
| 일관성 | ACID 트랜잭션이 기본 | 제품마다 달라서 최종 일관성인 경우가 많음 |

NoSQL은 네 종류로 나뉘어요.

- **문서형**: JSON 형태로 저장해요 (MongoDB).
- **키-값형**: 캐시와 세션에 써요 (Redis).
- **컬럼형**: 대량 쓰기와 분석에 써요 (Cassandra).
- **그래프형**: 관계 탐색에 써요 (Neo4j).

**선택 기준**

- 결제나 재고처럼 정합성이 중요하면 SQL이 맞아요.
- 데이터 관계가 복잡하고 통계 쿼리가 많아도 SQL이 맞아요.
- 구조가 자주 바뀌거나 트래픽이 매우 커서 서버를 계속 늘려야 하면 NoSQL이 맞아요.
- 캐시나 실시간 데이터처럼 빠른 읽기와 쓰기가 필요해도 NoSQL이 맞아요.

경계는 예전만큼 뚜렷하지 않아요. MongoDB도 다중 문서 트랜잭션을 지원하고, PostgreSQL도 JSON 컬럼을 지원해요. 확실하지 않으면 SQL로 시작하는 편이 안전해요. 나중에 병목이 생긴 부분만 NoSQL로 분리해도 늦지 않아요.

만들려는 서비스를 알려 주면 어느 쪽이 맞는지 골라 드릴게요.
