<!-- Q: 사이드 프로젝트 백엔드로 Supabase랑 Firebase 중에 뭐가 나아요? -->

**대부분의 사이드 프로젝트는 Supabase를 추천해요.** 데이터가 Postgres(SQL)라서 관계형 데이터를 다루기 쉽고, 나중에 다른 곳으로 옮기기도 편해요.

| 기준 | Supabase | Firebase |
|---|---|---|
| DB | Postgres (SQL, 조인, 트랜잭션) | Firestore (NoSQL, 조인 없음) |
| 종속성 | 오픈소스, 셀프호스팅 가능 | 구글 전용, 이전 어려움 |
| 실시간/오프라인 | 실시간 지원, 오프라인 동기화는 약함 | 실시간과 오프라인 동기화 모두 강함 |
| 모바일 SDK·푸시·분석 | 기본적인 수준 | 성숙함 (FCM, Crashlytics, Analytics) |
| 무료 티어 | 프로젝트가 일정 기간 비활성이면 일시 중지됨 | 중지 없음, 사용량 기반 과금 |

**Firebase가 나은 경우:**
1. 모바일 앱이 중심이고 푸시 알림, 크래시 리포트가 필요할 때
2. 오프라인 우선 동작이 핵심일 때
3. SQL을 전혀 쓰고 싶지 않을 때

**Supabase가 나은 경우:**
1. 웹 앱이거나 데이터에 관계(유저-게시글-댓글 등)가 있을 때
2. 요금이 갑자기 늘어나는 게 걱정될 때 (Firestore는 읽기 횟수 단위로 과금돼서 예측하기 어려워요)
3. 나중에 벤더를 바꿀 가능성이 있을 때

요금과 무료 티어 조건은 자주 바뀌니, 선택 전에 각 공식 가격 페이지에서 확인해 보세요.

어떤 종류의 앱인지(웹/모바일, 핵심 기능) 알려주시면 둘 중 하나로 확정해 드릴게요.
