<!-- Q: HTTPS를 쓰면 URL의 쿼리 파라미터도 암호화돼요? -->

네, 전송 중에는 암호화돼요. 다만 완전히 안전한 건 아니에요.

**암호화되는 것**
- 쿼리 파라미터(`?token=abc&id=123`), URL 경로(`/users/123/orders`), HTTP 헤더, 요청/응답 본문은 모두 TLS로 암호화돼서 네트워크 중간자(와이파이, ISP 등)는 볼 수 없어요.

**암호화되지 않는 것**
- 도메인 이름(호스트): TLS 핸드셰이크의 SNI와 DNS 조회 때문에 어떤 사이트에 접속하는지는 보일 수 있어요. (ECH, DoH 등을 쓰면 줄어들어요.)
- IP 주소와 접속 시점, 트래픽 양.

**그래도 쿼리 파라미터에 민감 정보를 넣으면 안 되는 이유**
전송 구간 밖에서 노출되기 때문이에요.
- 브라우저 방문 기록과 자동완성에 남아요.
- 서버 접근 로그, 프록시, CDN, 로드밸런서 로그에 URL 전체가 기록되는 경우가 많아요.
- `Referer` 헤더를 통해 다른 사이트로 새어나갈 수 있어요. (`Referrer-Policy`로 완화 가능)
- URL을 복사해 공유하거나 북마크하면 그대로 퍼져요.
- 모니터링/분석 도구(APM, Analytics)에 수집될 수 있어요.

**실무 권장**
- 비밀번호, API 키, 세션 토큰 같은 민감 정보는 `Authorization` 헤더나 POST 본문으로 보내세요.
- 부득이하게 URL에 토큰을 넣어야 한다면(예: 이메일 인증 링크) 일회용이고 만료 시간을 짧게 두세요.
