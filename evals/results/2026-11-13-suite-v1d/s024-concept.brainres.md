<!-- Q: OAuth랑 JWT 차이가 뭐예요? -->

OAuth는 "권한을 위임하는 절차(프로토콜)"이고, JWT는 "정보를 담은 토큰의 형식"이라서 서로 비교 대상이 아니라 층위가 달라요.

**OAuth 2.0**
- 목적: 앱이 사용자 비밀번호 없이 다른 서비스의 자원에 접근하게 허용하는 방법이에요.
- 예: "구글로 로그인", "이 앱이 내 구글 캘린더를 읽도록 허용".
- 흐름만 정의해요. 토큰이 어떤 모양인지는 정하지 않아요.

**JWT (JSON Web Token)**
- 목적: 서명된 JSON 데이터를 `header.payload.signature` 형태로 담는 토큰 형식이에요.
- 서버가 DB 조회 없이 서명만 검증해서 사용자를 확인할 수 있어요.
- 인증 방식이 아니라 데이터 포장 방식이라, OAuth 없이도 쓸 수 있어요.

**둘의 관계**

| 구분 | OAuth 2.0 | JWT |
|---|---|---|
| 정체 | 인가 프로토콜 | 토큰 포맷 |
| 답하는 질문 | 누가 무엇을 허용받나? | 토큰 안에 무엇이 있나? |
| 단독 사용 | 가능 (불투명 토큰 사용) | 가능 (자체 로그인 세션 등) |

OAuth의 access token을 JWT로 발급하는 경우가 많아서 헷갈리기 쉬워요. 하지만 불투명한 랜덤 문자열을 써도 OAuth는 성립해요.

**주의할 점**: JWT의 payload는 암호화가 아니라 Base64 인코딩이라 누구나 읽을 수 있어요. 비밀번호 같은 민감한 값은 넣으면 안 돼요. 또 발급 후에는 만료 전까지 폐기하기 어려워서, 만료 시간을 짧게 잡는 게 좋아요.

어떤 상황에 쓰려고 하시는지 알려주시면(소셜 로그인, 자체 API 인증 등) 맞는 구성을 골라드릴게요.
