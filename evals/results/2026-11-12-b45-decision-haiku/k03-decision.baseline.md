<!-- Q: 개인 프로젝트 배포할 건데 Vercel이랑 AWS 중에 뭐가 나아? -->

**개인 프로젝트라면 보통 Vercel이 낫습니다.** 단, 프로젝트 종류에 따라 답이 달라집니다.

| 상황 | 추천 |
|---|---|
| Next.js, React, Vue 같은 프론트엔드 또는 풀스택 웹앱 | **Vercel** |
| 정적 사이트, 블로그, 포트폴리오 | **Vercel** (또는 Netlify, Cloudflare Pages) |
| Express/FastAPI 같은 백엔드 API, 상시 실행 서버 | Vercel도 가능하지만 제약이 있어서 **Render, Railway, Fly.io** 같은 곳이 더 편할 수 있음 |
| 컨테이너, 워커, 크론, 대용량 데이터, 특정 AWS 서비스 연동이 필요함 | **AWS** |
| AWS를 배우는 게 목적 | **AWS** (단, 과금 사고 주의) |

**Vercel의 장점**
- 깃허브 연결만 하면 푸시할 때마다 자동 배포됨
- 설정이 거의 없고 프리 티어로 개인 프로젝트에 충분함
- 미리보기 URL, HTTPS, 도메인 연결이 기본 제공됨

**Vercel의 주의점**
- 서버리스 함수라서 실행 시간 제한이 있음
- 트래픽이 많아지면 상업용 플랜에서 과금이 빠르게 늘어날 수 있음
- 데이터베이스는 별도로 준비해야 함 (Neon, Supabase 등과 조합)

**AWS의 장점과 단점**
- 장점: 자유도가 높고 확장성이 좋으며, 기술 스택을 세밀하게 통제할 수 있음
- 단점: 설정이 복잡하고, 잘못 설정하면 예상치 못한 요금이 나올 수 있음 (예산 알림 설정을 꼭 해두세요)

**정리하면**, 웹앱을 빠르게 올리는 게 목표라면 Vercel로 시작하고, 나중에 필요가 생기면 AWS로 옮기는 게 일반적인 순서입니다.

어떤 프로젝트인지(프레임워크, 백엔드 유무, 데이터베이스 사용 여부) 알려주시면 더 구체적으로 추천해 드릴게요.
