<!-- Q: 도커랑 가상머신 차이가 뭐야? -->

도커(컨테이너)와 가상머신(VM)의 핵심 차이는 **무엇을 가상화하느냐**입니다.

## 구조 차이

- **가상머신**: 하이퍼바이저(VMware, VirtualBox, KVM 등) 위에 게스트 OS 전체를 올립니다. VM마다 자체 커널을 가지고 있어 하드웨어를 가상화하는 방식입니다.
- **도커 컨테이너**: 호스트 OS의 커널을 공유하고, 프로세스를 namespace(격리)와 cgroup(자원 제한)으로 분리해 실행합니다. OS 수준을 가상화하는 방식입니다.

```
[VM]                         [Docker]
App A | App B                App A | App B
Bins/Libs | Bins/Libs        Bins/Libs | Bins/Libs
Guest OS | Guest OS          ---- Docker Engine ----
---- Hypervisor ----         ------ Host OS ------
------ Host OS/HW ------     ------ Hardware ------
```

## 비교

| 항목 | 가상머신 | 도커 컨테이너 |
|---|---|---|
| 격리 수준 | 강함 (커널까지 분리) | 상대적으로 약함 (커널 공유) |
| 크기 | 수 GB ~ 수십 GB | 수십 MB ~ 수백 MB |
| 시작 시간 | 수십 초 ~ 분 | 거의 즉시 (초 단위 이하) |
| 성능 오버헤드 | 큼 | 거의 네이티브에 가까움 |
| 자원 사용 | 무거움 (OS별 메모리/CPU 점유) | 가벼움 |
| 다른 OS 실행 | 가능 (Linux 호스트에서 Windows VM 등) | 호스트와 같은 커널 계열만 가능 |
| 이식성 | 이미지가 큼 | 이미지 기반으로 배포가 쉬움 |

## 언제 무엇을 쓰나

- **도커**: 마이크로서비스, 개발/테스트 환경 통일, CI/CD, 빠른 배포와 확장이 필요할 때
- **VM**: 강한 보안 격리, 서로 다른 OS 필요, 레거시 애플리케이션, 멀티테넌트 환경

## 참고

- Mac/Windows에서 도커를 쓰면 내부적으로 경량 Linux VM을 띄우고 그 안에서 컨테이너를 실행합니다. 컨테이너는 Linux 커널이 필요하기 때문입니다.
- 둘은 대체 관계가 아니라 함께 쓰는 경우도 많습니다. 예를 들어 클라우드의 VM 위에서 도커 컨테이너를 돌리는 방식입니다.
