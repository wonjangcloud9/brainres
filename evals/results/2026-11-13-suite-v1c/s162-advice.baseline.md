<!-- Q: 개발자로 이직할 때 포트폴리오에 뭘 넣어야 해요? -->

개발자 이직용 포트폴리오에는 아래 내용을 넣는 걸 추천해요.

## 1. 핵심 구성
- **자기소개**: 2~3줄로 포지션(백엔드, 프론트엔드 등), 강점, 관심 분야를 요약
- **연락처와 링크**: GitHub, 블로그, LinkedIn, 이메일
- **기술 스택**: 나열만 하지 말고 "실무에서 써본 것 / 개인 프로젝트에서 써본 것"으로 구분

## 2. 프로젝트 (가장 중요)
3~5개 정도로 추려서, 각각 아래를 담으세요.
- **한 줄 설명**과 만든 이유
- **내 역할과 기여도** (팀 프로젝트면 특히 중요)
- **사용 기술**과 선택 이유
- **문제 해결 경험**: 어떤 문제가 있었고, 어떻게 원인을 찾고, 어떻게 해결했는지
- **성과를 수치로**: "응답 속도 40% 개선", "월 사용자 N명", "테스트 커버리지 80%" 등
- **링크**: 라이브 데모, GitHub 저장소, 아키텍처 다이어그램, 스크린샷

## 3. 경력 (있다면)
- 회사/기간/직무
- 담당 업무보다 **성과와 임팩트** 중심으로 작성
- 협업 경험(코드 리뷰, 장애 대응, 기획/디자인과의 협업)

## 4. 있으면 좋은 것
- 기술 블로그 글 (트러블슈팅, 학습 정리)
- 오픈소스 기여
- 발표, 스터디, 사이드 프로젝트
- 자격증, 수상 (보조 자료로만)

## 5. 작성 팁
- **양보다 질**: 튜토리얼 따라 만든 프로젝트 여러 개보다 깊이 있는 하나가 낫습니다.
- **지원 직무에 맞추기**: 백엔드 지원이면 API 설계, DB, 성능, 인프라 경험을 앞에 배치하세요.
- **README를 신경 쓰기**: 실행 방법, 구조, 주요 기능이 바로 보이게 정리하세요.
- **코드 품질**: 불필요한 파일, 키/비밀번호 노출, 엉망인 커밋 메시지는 정리하세요.
- **읽기 쉽게**: 면접관은 한 포트폴리오에 몇 분밖에 안 쓰므로, 핵심이 첫 화면에 보이게 하세요.

## 6. 흔한 실수
- 기술 스택만 길게 나열하고 어떤 문제를 풀었는지 없음
- 팀 프로젝트에서 본인 기여가 불명확함
- 링크가 깨져 있거나 데모가 동작하지 않음
- 신입/주니어가 지나치게 많은 프로젝트를 넣어 깊이가 얕아 보임

원하시면 지원하려는 직무(프론트/백엔드 등)와 경력 연차를 알려주세요. 거기에 맞춰 구성안이나 프로젝트 설명 문구 예시를 더 구체적으로 짜드릴게요.
